A function registered with `expr.Function` can override a builtin of the same name, such as `upper` or `trim`, and a direct call uses it: with `expr.Function("upper", ...)`, the expression `upper('str')` calls the user's function. Called through a pipeline, `'str' | upper()`, it doesn't: the pipeline doesn't reach the user's function for every builtin name. A pipeline must call the overriding function exactly as a direct call does, for every builtin name. `go test ./...` must pass.
