Add bytes literals to the expression language: a string literal preceded by `b` or `B`, such as `b"abc"` or `b'abc'`, evaluates to a `[]byte`, so `b"abc"` gives `[97 98 99]` and `data == b"test"` compares with a `[]byte` in the environment. In a bytes literal, `\x` and octal escapes are raw byte values from 0 to 255 (`b'\x00\xff'` is `[]byte{0, 255}`, `b'\101\102\103'` is `"ABC"`), the usual escapes such as `\n` work, and other characters are their UTF-8 bytes. `\u` and `\U` escapes are compile errors in a bytes literal, reported with the lexer's existing error for a bad escape, `unable to unescape string`, at the literal's position. The lexer emits a new token kind `Bytes` (in `parser/lexer`) whose `Value` is the raw bytes as a string, and the parser produces a new `ast.BytesNode` with a `Value []byte` field. `go test ./...` must pass.
